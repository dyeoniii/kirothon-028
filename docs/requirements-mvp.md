# 1일 MVP 요구사항 — 확정본

## 목표·대상
- 일반 사용자가 쓰는 **모바일 우선 반응형 웹앱**.
- 사용 흐름: `사건 생성 → SNS 공유 URL / 직접 URL / 텍스트 / 스크린샷 입력 → 댓글 선택 → AI 판독 → 선택적 증거 보관 → 추가 정보 확인 → PDF 2종 다운로드`.
- 제품명은 가칭 'Catch Trolls'. 현재 파일에서 가칭으로 쓰던 'Don't feed the trolls'는 부제/슬로건 후보로만 남긴다.
- **4개 Kiro Crew 세션은 유지한다**(2명 × 2세션). 세션은 담당 폴더를 분리하여 충돌 방지.

## P0 필수 구현
- [R-01] React/TypeScript/Vite/Tailwind 기반 모바일 반응형 사건 목록·상세·분석 UI.
- [R-02] 텍스트 붙여넣기 및 사용자가 원하는 줄 단위 댓글 분리·검토. 원본 게시글 맥락을 추가 입력할 수 있어야 함.
- [R-03] 이미지 업로드(.png/.jpg/.jpeg/.webp, 최대 10MB/파일) → 멀티모달 LLM 댓글 추출. 이미지 내 작성자·시간을 읽지 못하면 **추측하지 않고 null**. 다중 이미지/대화 재구성은 P1.
- [R-04] URL 직접 입력 및 출처 저장. YouTube `watch`, `youtu.be`, `shorts` URL에서 영상 ID를 파싱하고 **공개 접근 가능한 댓글 최대 200개(최상위+가져올 수 있는 답글 합계)** 표시. 답글은 필요시 `comments.list` 페이지 조회, API 한도/비공개/댓글 비활성화 시 오류·대체 입력 제공. **다른 플랫폼은 URL 출처 저장 + 수동 텍스트/이미지 입력.**
- [R-05] **SNS 공유/URL 입력을 둘 다 1차 MVP에 포함**. 모바일에서 URL 공유 → 지원 브라우저의 설치형 PWA가 Web Share Target(`GET /share-target?url=...`)으로 수신 → 입력 화면 자동 채움. 미지원 OS/브라우저·미설치 시 링크 복사-붙여넣기. 인스타그램 자동 수집을 의미하지 않음.
- [R-06] 선택 댓글에 실제 Gemini JSON 기반 판독(legal_review / needs_context / low_risk); 문제 문구 인용, 이유, 검토 쟁점, 추가 확인 질문 포함. 범죄 여부 확정 금지. `mock` 모드는 개발·장애 시 대체만.
- [R-07] 사건 생성/목록/상세, 증거 saved 상태, 원본 이미지/URL/댓글/AI 분석을 영속적으로 저장. SHA-256, `collected_at` 기록. 저장 전/후 원문 수정 금지.
- [R-08] 저장 증거의 누락 정보 체크리스트와 사용자 답변 저장. **체크리스트 중심 구현**(LLM 기반 질문 생성은 시간이 허락하면), 퍼센트는 임의 법적 충분성 점수가 아닌 *서비스 내 항목 작성률*로 표기.
- [R-09] PDF 2종: 사건 경위서 + 증거 목록. 한국어, 원본 출처/시간, '확인된 사실 / AI 분석 추정' 분리, 법률 자문 아님 고지. 보고서에는 존재하지 않는 사실을 창작하지 않음.
- [R-10] 삭제: 사건 삭제 시 관계 댓글·판독·업로드 원본을 함께 삭제. 파일 크기·형식 검증, 키 비노출, 외부 LLM 전달 자료 최소화.

## P1 (P0 종료 후만)
- 복수 스크린샷 대화 연결 및 반복 작성자 묶음, 상담용 요약서 PDF, 타임라인, 배포 자동화 개선.

## 제외
- 모든 SNS의 댓글 자동 수집, 실사용자 로그인/멀티테넌시, 고소장 작성 대행, 법적 승소 예측, 변호사 연결, LangGraph 워크플로우, Embedding.
- 외부 공개 배포/실제 피해자 실명 데이터 사용: 인증 없는 로컬 시연이므로 금지.

## 제약 및 위험
- YouTube API 키·할당량·비공개·답글 수집 제한 발생 가능. 접근 실패 자체를 사용자에게 보여주는 기능 필요.
- PWA Web Share Target은 설치 및 지원 브라우저가 필요하고 **특히 iOS에서 수신 지원을 가정하면 안 됨**. PWA 설치가 없는 일반 웹 사용자는 붙여넣기 경로 사용.
- 이미지 OCR에서 추출한 작성자/시간은 오인식할 수 있으므로 저장 전에 확인 가능해야 함.
- 원본 증거의 무결성: 원본 파일은 그대로 보존, 텍스트 추출본·AI 추정과 구분.

## 데모 성공 시나리오
1. 새 사건 생성 후 일반 댓글을 텍스트로 입력 → 판독 3단계 중 하나 표시.
2. 두 개 이상 댓글 선택 → 분석 → 원하는 댓글만 증거함에 저장.
3. 가상 댓글 스크린샷 → 댓글 리스트로 추출 → 사용자가 인식 내용을 확인.
4. YouTube URL → 공개 댓글 조회 (차단/쿼터 시 명확한 실패 안내).
5. 지원되는 PWA 환경에서 SNS 공유 → URL 자동 채움; 미지원 환경은 직접 URL 입력.
6. 누락 항목 확인·답변 저장 → 사건 경위서/증거 목록 PDF가 저장된 사실과 일치.
