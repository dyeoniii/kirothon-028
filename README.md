# Catch Trolls

**악성 댓글을 마주한 사용자가 SNS 댓글을 수집하고, AI 분석을 참고해 증거를 보완·정리한 뒤 상담용 문서까지 준비할 수 있도록 돕는 웹 서비스.**

**Demo**

- https://potato-kq1a.onrender.com/
- https://drive.google.com/drive/folders/1f1KFXqVSaywtSjYHdWXRdt3ubrJI7tPU?usp=sharing

> Catch Trolls는 법률 자문이나 범죄 성립 여부에 대한 확정적 판단을 제공하지 않습니다. AI 분석 결과는 참고자료이며, 최종 판단은 관련 전문가와 확인해야 합니다.

---

## 1. 문제 정의

### 대상 사용자

SNS 게시물이나 영상의 악성 댓글을 경험했지만, 어떤 댓글을 기록하고 어떤 증거를 준비해야 할지 막막한 일반 사용자. 특히 법률 용어에 익숙하지 않고 댓글이 여러 게시물에 흩어져 있는 사용자를 대상으로 합니다.

### 문제 상황

악성 댓글을 발견한 사용자는 댓글 원문, 게시물 주소, 작성 시점 등 관련 내용을 따로 저장해야 합니다. 댓글이 삭제되거나 내용이 바뀌기 전에 기록해야 한다는 부담도 있습니다. 그러나 단순 캡처만으로 어떤 정보가 충분한지 알기 어렵고, 상담을 받으려면 흩어진 기록을 다시 정리해야 합니다.

### 기존 방식과 한계

- **수동 캡처·복사:** 원문과 출처 정보가 서로 분리되기 쉽고, 누락 여부를 확인하기 어렵습니다.
- **개별적인 검색 및 상담 준비:** 어떤 자료가 중요한지 찾는 과정이 반복되고, 사건 경위 정리에 시간이 듭니다.
- **일반적인 AI 채팅:** 댓글을 설명받을 수는 있어도 사건별 증거 축적, 추가 보완 질문, PDF 문서화까지 하나의 흐름으로 관리하기 어렵습니다.

### 근거

본 프로젝트는 악성 댓글을 저장하고 상담 자료를 준비하는 과정에서 **수집 → 분류 → 누락 확인 → 문서 정리**가 서로 분절된다는 문제 가설에서 출발했습니다. 현재 제출 가능한 사용자 설문·사용성 테스트 수치가 확인되지 않아 정량 효과를 사실로 주장하지 않습니다.

- **제출 전 보완:** 사용자 인터뷰/테스트가 있다면 참여 인원, 실제 소요시간, 응답 결과와 출처를 이곳에 기록해 주세요.
- **정량적 성과는 측정 전까지 목표치와 실측치를 구분**합니다.

### 목표

사용자가 SNS URL·텍스트·스크린샷 가운데 편한 방식을 선택하여 댓글을 수집하고, AI 분석 근거와 증거 보완 항목을 확인한 뒤, 사건 경위서와 증거자료 목록을 PDF로 정리하는 **하나의 연속된 작업 흐름**을 제공합니다.

## 2. 핵심 기능

| 기능 | 해결하는 불편 | 관련 코드 영역 |
|---|---|---|
| 사건 생성·조회·관리 | 여러 댓글과 자료가 뒤섞이는 문제 | `frontend/src/pages/`, `backend/app/`의 사건 API 및 모델 |
| SNS URL 입력 및 댓글 가져오기 | 게시물과 댓글을 수동으로 옮겨 적는 번거로움 | `frontend/src/api/client.ts`, `backend/app/collectors/` |
| 텍스트·스크린샷 입력 | 원본 URL을 확보하기 어려운 상황 | `frontend/src/pages/`, `backend/app/collectors/` 및 이미지 처리 모듈 |
| AI 댓글 분석 | 어떤 부분을 우선 검토할지 판단하기 어려움 | `backend/app/analysis/`, 프론트엔드 판독 결과 화면 |
| 증거 보완 질문·체크리스트 | 필요한 정황과 자료의 누락을 알아차리기 어려움 | `backend/app/analysis/`의 검토 기능, 사건 상세의 보완 탭 |
| 증거 정리·메모 | 원문, 출처, 사용자 메모를 분리 관리하는 불편 | 사건·댓글 API, `frontend/src/pages/CaseDetailPage.tsx` |
| 사건 경위서·증거목록 PDF | 상담 전에 자료를 다시 편집해야 하는 번거로움 | `backend/app/documents/`, 문서 탭 |
| 반응형 웹 및 공유 진입점 | 스마트폰에서 자료를 옮기는 번거로움 | `frontend/src/`, `frontend/src/pages/ShareTargetPage.tsx` |

> 실제 SNS 수집 범위, 이미지 OCR 및 외부 AI 호출 가능 여부는 각 API 자격증명과 플랫폼 제약에 따라 달라질 수 있습니다. 경로는 프로젝트의 개발 구조를 기준으로 적었으며, 제출 직전 최종 저장소와 대조해 주세요.

## 3. 사용 시나리오

1. 사용자가 Catch Trolls에 접속하여 새 사건을 만들거나 기존 사건을 선택합니다.
2. **SNS URL → 텍스트 → 스크린샷** 중 하나를 선택해 댓글을 가져오거나 입력합니다. 입력 탭에 진입하면 SNS URL을 먼저 보여주는 흐름을 지향합니다.
3. 수집된 댓글에 AI 판독을 요청하고, 위험 신호·검토 쟁점·판단 근거를 확인합니다.
4. 보관할 댓글을 선택하고 출처와 메모를 정리합니다.
5. 증거 보완 체크리스트 및 추가 질문으로 누락 정보를 확인합니다.
6. 사건 경위서와 증거자료 목록 PDF를 생성하여 상담 자료로 활용합니다.

## 4. 기대 효과

| 지표 | 기대하는 변화 | 검증 상태 |
|---|---|---|
| 댓글 입력 방식 | SNS URL, 텍스트, 스크린샷 **3가지 경로** 제공 | 기능별 동작 점검 필요 |
| 상담용 산출물 | 사건 경위서, 증거자료 목록 **2종 PDF** 제공 | PDF 다운로드·한글 출력 점검 필요 |
| 증거 정리 과정 | 수집·AI 검토·보완·문서 생성을 **하나의 서비스 흐름**으로 통합 | 시나리오 테스트 필요 |
| 소요시간 | 수동 수집 및 정리 대비 감소 기대 | 사용자 실측 전이므로 절감 시간 미기재 |

**향후 측정 계획:** 같은 댓글 묶음을 대상으로 수동 정리와 Catch Trolls 사용을 비교하여 완료 시간(분), 누락한 증거 항목 수(개), 과업 성공률(%)을 측정합니다. 결과 확보 후 목표치가 아니라 실제 관측값을 기재합니다.

## 5. 차별점

1. **댓글 판독에서 끝나지 않는 워크플로우:** 댓글 수집부터 증거 보완, PDF 출력까지 연결합니다.
2. **사건 중심 정리:** 댓글을 각각 판단하는 데서 그치지 않고 같은 사건의 자료로 묶어 관리합니다.
3. **보완 가능한 증거 기록:** AI가 판단 근거뿐 아니라 추가 확인이 필요한 정보를 제안하도록 설계했습니다.
4. **입력 접근성:** URL, 직접 입력, 이미지라는 서로 다른 자료 보유 상황을 지원합니다.
5. **신중한 안내:** AI 결과를 법적 확정 판단으로 표현하지 않고 전문 상담 준비를 돕는 보조 도구로 위치시킵니다.

## 6. 설치와 실행

### 사전 준비

- Python 3.13 권장(실제 의존성 호환 버전은 배포 Dockerfile 기준 확인)
- Node.js 및 npm
- 코드에서 요구하는 AI·SNS API 키(실제 연동 시)

```bash
# 1. 저장소 다운로드
git clone https://github.com/dyeoniii/Potato.git
cd Potato

# 2. 백엔드 가상환경 생성 및 의존성 설치
python3 -m venv venv
source venv/bin/activate
python -m pip install -r backend/requirements.txt

# 3. 백엔드 실행 (터미널 1)
python -m uvicorn app.main:app --app-dir backend \
  --host 127.0.0.1 --port 8000 --reload --reload-dir backend

# 4. 프론트엔드 의존성 설치 및 실행 (터미널 2)
cd frontend
npm install
# frontend/.env.local 파일에서 VITE_USE_MOCK=false 설정 후
npm run dev
```

프론트엔드 개발 서버는 `vite.config.ts`의 `/api` 프록시를 통해 `127.0.0.1:8000` FastAPI로 연결됩니다. 백엔드만 확인하려면 `http://127.0.0.1:8000/api/health`에 접속합니다.

**Mock UI 확인:** `frontend/.env.local`에서 `VITE_USE_MOCK=true`로 설정하고 프론트엔드를 재시작합니다. Mock 모드의 AI 결과는 실시간 분석 결과가 아닙니다.

**배포:** Render Docker Web Service가 `main` 브랜치의 루트 Dockerfile을 빌드해 React 정적 파일과 FastAPI를 한 서버에서 제공하도록 구성했습니다. 환경변수는 Render의 Environment에 등록하고 `.env`/API 키는 저장소에 커밋하지 않습니다. 무료 인스턴스의 SQLite 및 업로드 파일은 영구 보존되지 않으므로 실사용 데이터 입력에 주의해야 합니다.
